# OpenDog Android 第一阶段实现方案

## 1. 当前工程状态

当前项目是一个最小 Android 应用：

- 包名：`com.example.opendog`
- 技术栈：Kotlin + Jetpack Compose + Material3
- 入口文件：`app/src/main/java/com/example/opendog/MainActivity.kt`
- 现状：只有空白 Compose 页面，尚未接入无障碍服务、本地存储、网络上传和配置管理。

第一阶段目标是跑通最小链路：

```text
AccessibilityService
        ->
PageSnapshotExtractor
        ->
PageStabilityController
        ->
EventBuilder
        ->
Room 本地事件
        ->
IngestClient
        ->
服务器 /ingest
```

第一阶段只处理应用或页面切换产生的 `focus_switch` 事件，不做截图、OCR、点击分析、滚动分析、输入分析、自动后台补传和本地 AI 总结。

## 2. 依赖与工程配置

### 2.1 Gradle 依赖

需要在 `gradle/libs.versions.toml` 和 `app/build.gradle.kts` 中补充以下能力：

- Room：保存事件和上传状态。
- Kotlin Serialization 或 Gson/Moshi：生成事件 JSON 和请求 JSON。
- OkHttp 或 Retrofit：请求服务器 `/ingest`。
- Lifecycle ViewModel：让主界面观察状态。
- DataStore Preferences：保存服务器地址、Token、device_id。

建议第一阶段使用：

- `androidx.room:room-runtime`
- `androidx.room:room-ktx`
- `androidx.room:room-compiler`，配合 KSP 或 KAPT
- `androidx.datastore:datastore-preferences`
- `com.squareup.okhttp3:okhttp`
- `org.jetbrains.kotlinx:kotlinx-serialization-json`
- `androidx.lifecycle:lifecycle-viewmodel-compose`

### 2.2 Manifest 与无障碍配置

在 `AndroidManifest.xml` 中注册 `OpenDogAccessibilityService`：

```xml
<service
    android:name=".accessibility.OpenDogAccessibilityService"
    android:exported="true"
    android:permission="android.permission.BIND_ACCESSIBILITY_SERVICE">
    <intent-filter>
        <action android:name="android.accessibilityservice.AccessibilityService" />
    </intent-filter>
    <meta-data
        android:name="android.accessibilityservice"
        android:resource="@xml/opendog_accessibility_service" />
</service>
```

新增 `app/src/main/res/xml/opendog_accessibility_service.xml`：

```xml
<accessibility-service xmlns:android="http://schemas.android.com/apk/res/android"
    android:accessibilityEventTypes="typeWindowStateChanged|typeWindowContentChanged"
    android:accessibilityFeedbackType="feedbackGeneric"
    android:accessibilityFlags="flagReportViewIds|flagRetrieveInteractiveWindows"
    android:canRetrieveWindowContent="true"
    android:notificationTimeout="100" />
```

## 4. 模块设计

### 4.1 MainActivity / MainViewModel

职责：

- 显示无障碍服务是否开启。
- 提供“打开无障碍设置”按钮。
- 输入并保存服务器地址、Token、device_id。
- 显示当前页面识别结果：包名、类名、focus_id、文字长度、部分文字。
- 显示本地 `PENDING` 数量、最近上传结果、最近错误。
- 提供“重新上传”按钮，手动触发补传。

实现要点：

- 打开无障碍设置使用 `Settings.ACTION_ACCESSIBILITY_SETTINGS`。
- 无障碍状态通过 `Settings.Secure.ENABLED_ACCESSIBILITY_SERVICES` 判断。
- Token 输入框默认使用密码显示，避免明文长时间暴露。
- 页面状态可先用内存 `StateFlow` 暴露，后续再考虑持久化。

### 4.2 OpenDogAccessibilityService

职责：

- 监听 `TYPE_WINDOW_STATE_CHANGED` 和 `TYPE_WINDOW_CONTENT_CHANGED`。
- 排除 `com.example.opendog` 自身包名。
- 获取 `rootInActiveWindow`。
- 调用 `PageSnapshotExtractor` 生成页面快照。
- 调用 `PageStabilityController` 判断是否稳定且是否切换。
- 稳定切换后调用 `EventBuilder`、`EventRepository`、`IngestClient`。

注意点：

- Service 不直接拼接 JSON 细节，避免逻辑集中到一个文件。
- `rootInActiveWindow` 可能为 `null`，此时允许生成空文本快照或跳过。
- 所有耗时操作放入协程 `Dispatchers.IO`。
- 同一 `focus_id` 不重复生成事件。

### 4.3 PageSnapshotExtractor

输入：

- `AccessibilityEvent`
- `AccessibilityNodeInfo?`

输出：

```kotlin
data class PageSnapshot(
    val packageName: String,
    val className: String,
    val windowId: Int?,
    val title: String,
    val text: String,
    val focusId: String
)
```

提取规则：

- `packageName` 优先取事件 packageName。
- `className` 优先取事件 className。
- `focusId = "$packageName/$className"`。
- 遍历节点树，读取 `text` 和 `contentDescription`。
- 删除空字符串。
- 使用 `LinkedHashSet` 去重，保留页面顺序。
- 多空格压缩为单空格。
- 用换行拼接。
- 最大长度限制为 10,000 字符。

### 4.4 PageStabilityController

职责：

- 收到候选快照后延迟 300 到 500 毫秒再次确认。
- 两次 `focusId` 一致才认为页面稳定。
- 维护 `currentFocusId`。
- 只有新旧 `focusId` 不同才返回“需要生成事件”。

建议策略：

- 使用 `CoroutineScope` 和 `Job`。
- 新事件到来时取消旧的 pending job。
- 延迟后再次调用 extractor 读取当前窗口。
- 稳定后更新 `currentFocusId`。

### 4.5 EventBuilder

职责：

- 为每条事件生成新的 UUID。
- 生成手机本地 Unix 时间戳，单位为秒，保留毫秒小数。
- 把 `PageSnapshot` 转换为服务端兼容事件。

事件格式：

```json
{
  "event_id": "UUID",
  "type": "focused_window_ocr",
  "ts": 1783502400.123,
  "data": {
    "trigger": "focus_switch",
    "focus_id": "com.android.chrome/ChromeTabbedActivity",
    "app": "com.android.chrome",
    "title": "页面标题",
    "text": "页面文字",
    "capture_method": "accessibility"
  }
}
```

固定值：

- `type = "focused_window_ocr"`
- `trigger = "focus_switch"`
- `capture_method = "accessibility"`

### 4.6 EventRepository / Room

Room 表：`events`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `event_id` | String | 主键 |
| `type` | String | 事件类型 |
| `ts` | Double | Unix 时间戳 |
| `data_json` | String | data 对象 JSON |
| `status` | String | `PENDING` / `SENT` / `FAILED` |
| `last_error` | String? | 最近错误 |
| `created_at` | Long | 本地创建时间 |
| `updated_at` | Long | 本地更新时间 |

Repository 方法：

- `insertPending(event)`
- `getPendingEvents(limit: Int)`
- `markSent(eventIds)`
- `markFailed(eventId, error)`
- `countPending()`
- `observeLatestStatus()`

关键约束：

- 事件必须先保存为 `PENDING`，再尝试上传。
- 断网或超时不改为 `FAILED`，保持 `PENDING`。
- 401 / 403 标记 `FAILED` 并提示 Token 错误。
- 400 / 422 标记 `FAILED` 并保存服务端错误。
- 409 或重复事件按成功处理，标记 `SENT`。

### 4.7 IngestClient

请求：

```json
{
  "source": "android_a",
  "device_id": "android_phone_001",
  "events": [
    {
      "event_id": "UUID",
      "type": "focused_window_ocr",
      "ts": 1783502400.123,
      "data": {}
    }
  ]
}
```

请求头：

```text
Authorization: Bearer <token>
Content-Type: application/json
```

实现策略：

- 第一阶段可以一次上传 1 到 20 条 `PENDING` 事件。
- 超时时间建议 10 秒。
- URL 由主界面配置，内部拼接 `/ingest`。
- 返回 `ok=true` 时标记成功。
- 网络异常返回明确错误类型给 Repository 和 UI。

### 4.8 AppConfig

使用 DataStore 保存：

- `server_base_url`
- `token`
- `device_id`

默认值建议：

- `source = "android_a"` 固定写在请求构造中。
- `device_id` 首次启动时生成一个稳定 ID，例如 `android_${UUID}`，允许用户在界面修改。
- `server_base_url` 初始为空，用户填写后才允许上传。

## 5. 实现顺序

### 第 1 步：主界面骨架

- 将 `MainActivity` 改造成配置和状态页面。
- 增加无障碍状态显示。
- 增加打开系统无障碍设置按钮。
- 增加服务器地址、Token、device_id 输入项。
- 增加当前页面和上传状态展示区域。

验收：

- App 可启动。
- 点击按钮能进入系统无障碍设置。
- 配置项重启后仍保留。

### 第 2 步：注册 AccessibilityService

- 新增 `OpenDogAccessibilityService`。
- 新增 `opendog_accessibility_service.xml`。
- 在 Manifest 注册服务。
- Logcat 打印收到的事件类型、包名、类名。

验收：

- 能在系统设置里看到 OpenDog 无障碍服务。
- 开启后切换 App，Logcat 能看到前台包名和类名。

### 第 3 步：页面文字提取

- 新增 `PageSnapshot` 和 `PageSnapshotExtractor`。
- 遍历节点树提取 `text` 和 `contentDescription`。
- 做去空、去重、压缩空格、长度限制。
- 将最近快照展示到主界面。

验收：

- Chrome、设置、普通列表页面能提取主要文字。
- 无文字页面允许 `text = ""`。
- OpenDog 自身不会被采集。

### 第 4 步：页面稳定判断

- 新增 `PageStabilityController`。
- 实现 300 到 500 毫秒延迟确认。
- 维护 `currentFocusId`。
- 同一 `focusId` 不重复触发。

验收：

- 从 App A 切到 App B 只生成一次候选结果。
- 同一页面内容轻微变化不会重复生成 `focus_switch`。

### 第 5 步：事件生成

- 新增 `OpenDogEvent` 和 `EventBuilder`。
- 生成 UUID、时间戳和标准 data。
- Logcat 打印生成的事件摘要，不打印完整 Token。

验收：

- 每次真实页面切换生成一条 `focused_window_ocr`。
- `data.trigger` 为 `focus_switch`。
- `data.capture_method` 为 `accessibility`。

### 第 6 步：Room 本地保存

- 新增 `EventEntity`、`EventDao`、`EventDatabase`、`EventRepository`。
- 事件先保存为 `PENDING`。
- 主界面展示待上传数量和最近事件状态。

验收：

- 断网时切换页面，事件仍保留在本地。
- 重启 App 后待上传数量仍正确。

### 第 7 步：上传 /ingest

- 新增 `IngestRequest`、`IngestResponse`、`IngestClient`。
- 保存成功后立即尝试上传。
- 增加手动“重新上传”按钮。
- 按 HTTP 状态码更新事件状态。

验收：

- 服务端收到 `source=android_a`。
- 服务端收到正确 `device_id`。
- 成功后本地事件标记为 `SENT`。
- 超时或断网时仍保持 `PENDING`。

### 第 8 步：异常和重复上传测试

- 测试 Token 错误。
- 测试服务端 400 / 422。
- 测试重复上传或 409。
- 测试网络恢复后手动补传。

验收：

- 401 / 403 在 UI 显示 Token 错误。
- 409 或重复事件按成功处理。
- 服务器不会因为重复上传产生重复数据。

## 6. 测试清单

### 真机功能测试

- 安装 App 后可正常启动。
- 能跳转无障碍设置。
- 开启无障碍服务后返回 App，状态显示为已开启。
- 切换到设置、Chrome、微信或其他普通 App 后，能显示包名和类名。
- 普通页面能显示部分页面文字。
- OpenDog 自身页面不产生采集事件。

### 本地存储测试

- 断网后切换页面，`PENDING` 数量增加。
- 重启 App 后 `PENDING` 数量不丢失。
- 上传成功后状态变为 `SENT`。
- 失败原因能显示在主界面。

### 上传测试

- 手工验证服务器 `/ingest` 返回 `{"ok": true}` 后再测试手机上传。
- 配置正确服务器地址和 Token 后，页面切换能上传事件。
- 服务端事件包含 `source=android_a`。
- 服务端事件包含正确 `device_id`。
- 服务端事件包含 `event_id`、`type`、`ts`、`data`。

### 去重测试

- 同一 App 内短时间停留，不重复生成同一个 `focus_id` 事件。
- 快速切换 App，稳定后只采集最终页面。
- 重新上传同一事件时，服务端 409 或重复响应按成功处理。

## 7. 风险与处理

| 风险 | 处理 |
| --- | --- |
| 部分 App 无法通过无障碍读取文字 | 第一阶段允许 `text = ""`，不加入 OCR |
| `TYPE_WINDOW_CONTENT_CHANGED` 触发过多 | 使用稳定判断和 `currentFocusId` 去重 |
| 用户未开启无障碍服务 | 主界面明确显示状态并提供跳转设置按钮 |
| Token 配错 | 401 / 403 标记失败并在 UI 提示 |
| 网络不可用 | 事件保持 `PENDING`，用户手动重新上传 |
| OpenDog 采集自身 | 在 Service 中排除 `BuildConfig.APPLICATION_ID` |
| 服务端重复事件 | 使用 `event_id` 幂等，409 按成功处理 |

## 8. 第一阶段完成标准

完成后必须满足：

- 能正确开启 OpenDog 无障碍服务。
- 切换 App 后能获取包名、页面类名和 `focus_id`。
- 普通页面能提取主要文字。
- 页面切换只生成一条 `focus_switch` 事件。
- 不采集 OpenDog 自身。
- 事件先保存到 Room，再尝试上传。
- 断网时事件不丢失，保持 `PENDING`。
- 网络恢复后可以手动补传。
- 服务端收到 `source=android_a`。
- 服务端收到正确 `device_id`。
- 重复上传不会产生重复数据。

## 9. 建议优先交付版本

第一版代码实现建议只包含：

1. Compose 主界面配置和状态展示。
2. AccessibilityService 注册和包名、类名识别。
3. 页面文字提取。
4. `focus_id` 稳定判断和去重。
5. 标准事件生成。
6. Room 保存。
7. 手动和即时 `/ingest` 上传。

所有 OCR、截图、后台自动重试、复杂交互分析和 AI 总结都放到第二阶段以后。
